# LIMS（EMC 实验室）MVP 设计规格

- 日期：2026-09-04
- 工单：T-002
- 状态：待用户审查
- 范围：P1（MVP）；P2/P3 只列方向不展开

## 1. 背景与目标

10 人 EMC 检测实验室，约 100 单/月，当前用 Excel/Word/纸质管理。痛点：

1. 样品流转无留痕
2. 测试布置不标准（手工指定，易错）
3. 标准/文档流程管理缺失
4. 测试设备档案缺失
5. 原始记录管理缺失
6. 报告制作半天~一天/份（最耗时）
7. 报告模板无管理

**核心价值**：数据沿业务流自然沉淀，报告从"人工拼"变成"数据组装"；全程留痕满足 CMA/CNAS 认可体系要求。

**成功标准（P1）**：

- 主流程跑通：建委托 → 出报告，单据操作全程 ≤ 10 分钟
- 报告：数据齐全后生成 ≤ 5 分钟（对比人工半天~一天）
- 任一样品的流转历史可查（谁/何时/什么操作）
- 每个状态变更都有审计记录
- 三角色权限隔离生效（工程师访问不了客户档案等）

## 2. 范围

### P1（MVP，10 个模块）

| # | 模块 | 核心内容 |
|---|---|---|
| 1 | 认证与权限 | JWT 登录；三角色 RBAC，API 层强制 |
| 2 | 客户管理 | 客户档案：名称/联系人/行业/备注 |
| 3 | 委托管理 | 委托单创建（客户+样品+标准项目+要求）；生命周期状态机 |
| 4 | 样品管理 | 样品登记；状态机+流转留痕；照片/外观描述 |
| 5 | 标准库 | 标准（编号/名称/版本/生效日期）→ 测试项目（方法/判据/结果字段定义）；升版留旧版 |
| 6 | 排程日历 | 任务×日期×工程师×设备；日/周视图，按工程师或设备分组；拖拽排程；冲突高亮 |
| 7 | 原始记录 | 按字段定义结构化录入；自动判 pass/fail；附件；修订留痕不改原文 |
| 8 | 报告 | docxtpl Word 模板；委托单按样品拆多份；二级签发；状态机 |
| 9 | 审计留痕 | 全状态变更审计（人/时间/单据/动作/前后值） |
| 10 | 编号规则 | ⚠️ 占位，见 §7 专题讨论 |

### P1 明确不做（YAGNI）

自动排程、仪器数据采集直连、客户门户、钉钉、计费/财务、多租户/多实验室。

### P2 / P3 方向

- P2：设备档案与校准到期提醒、人员资质管理、文档流程管理（标准受控/升版审批）
- P3：钉钉对接（通知/审批）、客户门户（复用 API）

## 3. 领域模型

```
客户 ──< 委托单（聚合根，业务入口）
委托单 ──< 样品（状态机，流转留痕）
委托单 ──< 测试任务（= 标准项目 × 样品）
标准 ──< 测试项目（方法/判据/结果字段定义）
测试任务 >── 设备（P1 简表：名称/型号/暗室；档案校准属 P2）
测试任务 ── 原始记录（结构化结果 + 附件 + 修订痕）
委托单 ──< 报告（按样品拆分，编号关联委托单号）
人员（角色：业务/工程师/管理）
```

**关键决策**：

1. 委托单是聚合根，单据编号贯穿全程（留痕主线）
2. 任务 = 标准项目 × 样品 的配对，标准库先行 → 测试布置"从库勾选"，解决"布置不标准"
3. 原始记录结构化（字段定义来自标准库）→ 报告直接引用，解决"报告慢"
4. 报告按样品拆分：委托单 1 ── < 报告 N；报告编号 = 委托单号 + 批次后缀
5. 排程：完整日历但轻量——排得下、看得清、冲突可见，不做自动排程/资源优化

### 状态机

**委托单**：草稿 → 已确认 → 测试中 → 已出报告 → 已完成（任意非终态可 → 已终止）

**样品**：已登记 → 在测 → 已返 → 已报废（每次变更写流转留痕）

**测试任务**：未排程 → 已排程 → 测试中 → 完成（打回重测：完成 → 测试中，留痕）

**报告（二级签发）**：草稿 →（工程师自检）待签发 →（管理审核通过）已签发 → 已发放；管理审核打回 → 草稿（留打回原因）

## 4. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2 + Pydantic v2 + Alembic | API 自动文档、迁移管理 |
| 数据库 | PostgreSQL 16 | 单机 docker；10 人/100 单规模足够 |
| 前端 | Vite + TypeScript + React 18 + Ant Design 5 + FullCalendar | 表格/日历/表单为主力场景 |
| 报告 | docxtpl（Word 模板 + Jinja2） | 现有 Word 模板变一等公民，改模板不动代码 |
| 认证 | JWT（access + refresh），RBAC 在 API 层强制 | 角色：业务/工程师/管理 |
| 测试 | pytest + httpx（API）；Playwright（核心流程 E2E） | TestCommand: `pytest` |
| 部署 | docker compose：nginx（前端静态）+ api + postgres | 内网单机 |

## 5. 权限矩阵

| 模块 | 业务 | 工程师 | 管理 |
|---|---|---|---|
| 客户 | 管理 | **无权限** | 查看 |
| 委托 | 创建/编辑 | 查看 | 全量+终止 |
| 样品 | 登记/流转 | 查看 | 全量 |
| 标准库 | 查看 | 查看 | 维护/升版 |
| 排程 | 查看 | 查看+改自己的任务 | 全量 |
| 原始记录 | — | 录入/修订 | 查看 |
| 报告 | 查看 | 生成/自检 | **审核/签发**/发放 |
| 审计 | — | 查看本人 | 全量 |

注：委托单/任务页中工程师可见**客户名称**（测试上下文+报告需要），不可进客户档案详情。

## 6. 主流程（happy path）

```
业务：建委托单（选客户 + 勾选标准项目 + 样品信息）
  → 样品登记（编号 + 外观/照片）
管理/工程师：生成任务 → 排程日历拖拽（工程师 + 设备 + 日期）
工程师：按任务录入原始记录（结构化字段 + 判据自动判定 + 附件）
工程师：批次完成 → 生成报告（模板组装数据）→ 自检
管理：审核报告 → 签发 → 发放
业务：样品返还登记 → 委托单关闭
```

## 7. 编号规则（⚠️ 专题占位）

**P1 实施阻塞项**：委托单创建即需要编号，编号规则专题讨论必须在进行 P1 编码之前完成。

待讨论清单：

- 委托单号：格式（年份/流水/月份段？）、序列作用域（年/月/全局）、跨年处理
- 样品号：从属于委托单号（如 `委托号-S1`）还是独立序列
- 任务号：是否需要面向人的编号（还是仅内部 ID）
- 报告号：委托单号 + 批次后缀的具体格式（A/B vs 01/02）；拆分顺序规则
- 设备号：P2 才用，规则可后置
- 与现有 Excel/纸质编号的衔接：是否需要导入历史单据、历史编号段如何避让

暂定（仅防阻塞，可推翻）：委托单号 = `YYYYMMDD-NNN`（当日流水 3 位），报告号 = `委托单号-1` 递增。

## 9. 审计留痕设计

- 服务层统一切面：状态变更、字段修改、删除类操作自动写 `audit_logs`
- 记录内容：谁（user）、何时（时间戳）、对什么（单据类型+ID）、做了什么（动作）、前后值（JSON diff）
- 查询：管理角色可按单据/人/时间范围检索；样品流转时间线由 `sample_events` 专项视图呈现
- 不可修改：审计表只增不改不删
