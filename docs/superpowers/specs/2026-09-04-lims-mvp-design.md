## 1. 背景与目标

10 人 EMC 检测实验室，约 100 单/月，当前用 Excel/Word/纸质管理。痛点：

1. 样品流转无留痕
2. 测试布置不标准（手工指定，易错）
3. 标准/文档流程管理缺失
4. 测试设备档案缺失
5. 原始记录管理缺失
6. 报告制作半天~一天/份（最耗时）
7. 报告模板无管理

**核心价值**：数据沿业务流自然沉淀，报告从"人工拼"变成"数据组装"；全程留痕满足 CMA/CNAS 认可体系要求。

**成功标准（P1）**：

- 主流程跑通：建委托 → 出报告，单据操作全程 ≤ 10 分钟
- 报告：数据齐全后生成 ≤ 5 分钟（对比人工半天~一天）
- 任一样品的流转历史可查（谁/何时/什么操作）
- 每个状态变更都有审计记录
- 三角色权限隔离生效（工程师访问不了客户档案等）

## 2. 范围

### P1（MVP，13 个模块）

| # | 模块 | 核心内容 |
|---|---|---|
| 1 | 认证与权限 | JWT 登录；三角色 RBAC，API 层强制 |
| 2 | 客户管理 | 客户档案：编码/名称/联系人/行业/备注 |
| 3 | 报价管理 | 报价单（客户+标准项目+数量+报价）；状态机；**已落单一键转委托单** |
| 4 | 委托管理 | 委托单创建（可从报价转入）；生命周期状态机；确认时系统自动生成测试任务 |
| 5 | 样品管理 | 样品登记（业务线 EMC）；状态机+流转留痕；照片/外观描述 |
| 6 | 标准库 | 标准（官方号/名称/版本/生效日期）→ 测试项目（类别 EMI/EMS、方法/判据、**1→1 关联记录模板**）；升版留旧版 |
| 7 | 记录模板库 | 模板编号/名称/表单层级/类别/字段定义；受控；记录编号联动 |
| 8 | 排程日历 | 任务×日期×工程师×设备；日/周视图，按工程师或设备分组；拖拽排程；冲突高亮；EMI/EMS 筛选 |
| 9 | 原始记录 | 按记录模板结构化录入；自动判 pass/fail；附件；修订留痕不改原文；编号自动拼 |
| 10 | 报告 | docxtpl Word 模板；委托单按样品拆多份；二级签发；状态机 |
| 11 | 审计留痕 | 全状态变更审计（人/时间/单据/动作/前后值） |
| 12 | 编号规则 | 系统级编号服务，见 §7（已定稿） |
| 13 | 历史数据导入 | 明细级导入；系统赋新号，旧号存 external_no |

### P1 明确不做（YAGNI）

自动排程、仪器数据采集直连、客户门户、钉钉、计费/财务、多租户/多实验室。

### P2 / P3 方向

- P2：设备档案与校准到期提醒、人员资质管理、文档流程管理（标准受控/升版审批）
- P3：钉钉对接（通知/审批）、客户门户（复用 API）

## 3. 领域模型

```
客户 ──< 报价单（已落单 → 转委托单）
客户 ──< 委托单（聚合根，业务入口）
委托单 ──< 样品（状态机，流转留痕，业务线 EMC）
委托单 ──< 测试任务（= 标准项目 × 样品；类别 EMI/EMS 继承自项目）
标准 ──< 测试项目（类别/方法/判据）── 记录模板（表单层级/字段定义）
测试任务 >── 设备（P1 简表：名称/型号/暗室；档案校准属 P2）
测试任务 ── 原始记录（按模板实例化，编号含层级+模板号）
委托单 ──< 报告（按样品拆分，编号关联委托单号）
人员（角色：业务/工程师/管理）
```

**业务层级**：业务线（EMC，可扩展）→ 类别（EMI/EMS，标准项目必属其一）→ 标准（官方号）→ 测试项目 → 记录模板。
同一样品可既测 EMI 又测 EMS → 样品只带业务线段，EMI/EMS 是项目/记录级属性。

**关键决策**：

1. 委托单是聚合根，单据编号贯穿全程（留痕主线）
2. 报价→委托：已落单报价一键转委托单，客户/项目/样品信息继承
3. 任务 = 标准项目 × 样品 的配对，标准库先行 → 测试布置"从库勾选"，解决"布置不标准"
4. 原始记录按记录模板实例化（模板受控、字段结构化）→ 报告直接引用，解决"报告慢"
5. 报告按样品拆分：委托单 1 ── < 报告 N；报告编号 = 委托单号 + 批次后缀
6. 排程：完整日历但轻量——排得下、看得清、冲突可见，不做自动排程/资源优化
7. 测试工单与任务单合并：任务即工单，多任务可打印为一张工单页（视图，非实体）

### 状态机

**委托单**：草稿 →（业务确认，**系统自动生成测试任务**）已确认 →（首个任务开始测试）测试中 →（**全部**报告签发）已出报告 →（样品返还后业务**手动关闭**）已完成；任意非终态可 → 已终止

**样品**：已登记 → 在测 → 已返 → 已报废（每次变更写流转留痕）

**测试任务**：未排程 → 已排程 → 测试中 → 完成（打回重测：完成 → 测试中，管理触发、留原因）

**报告（二级签发）**：草稿 →（工程师自检）待签发 →（管理审核通过）已签发 → 已发放（P1 仅记录发放状态+时间，不约束发放方式）；管理审核打回 → 草稿（留打回原因）

## 6. 主流程（happy path）

```
业务：建报价单（客户 + 标准项目 + 数量 + 报价）→ 发出
客户接受 → 报价已落单 → 一键转委托单（继承客户/项目/样品信息）
  → 样品登记（编号 + 外观/照片）
  → 业务确认委托单 → 系统自动生成测试任务（标准项目 × 样品）
管理/工程师：排程日历拖拽（工程师 + 设备 + 日期）
工程师：按任务录入原始记录（按记录模板结构化 + 判据自动判定 + 附件）
工程师：批次完成 → 生成报告（模板组装数据）→ 自检
管理：审核报告 → 签发 → 发放
业务：样品返还登记 → 委托单关闭
```

## 7. 编号规则（已定稿，2026-09-04 专题讨论）

**统一骨架**：`前缀[-业务线][-层级][模板号]-YYYYMMDD-流水`，流水 3 位、**按日归零**（跨月归零自然满足）。

| 编号 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 报价单 | Q-日期-流水 | Q-20260904-001 | 全局/日 |
| 委托单 | C-日期-流水 | C-20260904-001 | 全局/日，主线 |
| 样品 | S-{业务线}-日期-流水 | S-EMC-20260904-001 | 业务线=EMC（伞类，可扩展）；不带 EMI/EMS（同样品可两类都测） |
| 任务/工单 | T-日期-流水 | T-20260904-001 | 全局/日；EMI/EMS 为属性不入号 |
| 技术记录 | TR{层}-{模板号}-日期-流水 | TR4-004-20250623-001 | 层级 1 位（见下） |
| 质量记录 | QR{层}-{模板号}-日期-流水 | QR4-001-20250623-001 | 同结构 |
| 报告 | R-{委托单号}-{批次} | R-C20260904-001-01 | 关联委托单号；批次 2 位 |
| 设备 | EQ-流水 | EQ-001 | 静态，P2 档案深化 |
| 客户 | CU-流水 | CU-001 | 静态 |

**表单层级（1 位码，入记录编号第 2 段）**：

| 码 | 含义 | 对应文档前缀 |
|---|---|---|
| 1 | 手册层级表单 | QM |
| 2 | 程序文件层级表单 | QP |
| 3 | 作业指导书层级表单 | WI |
| 4 | 纯记录表单（可与 2/3 重叠） | — |

**约定**：
- 标准库不自定义编号，用官方标准号（GB 9254-2008 等）
- EMI/EMS 类别是模板/项目/记录的**属性字段**，不入编号，列表/日历可筛选分组
- 文档体系编号（QM/QP/WI/QR 文档本身）属 P2 文档流程管理，P1 数据结构预留
- 序列服务：每前缀独立序列，DB 事务内取号防并发重复
- **历史导入：不兼容旧单号**——新序列从 001 起步不做避让；旧号存 `external_no` 字段，支持按旧号检索

## 9. 审计留痕设计

- 服务层统一切面：状态变更、字段修改、删除类操作自动写 `audit_logs`
- 记录内容：谁（user）、何时（时间戳）、对什么（单据类型+ID）、做了什么（动作）、前后值（JSON diff）
- 查询：管理角色可按单据/人/时间范围检索；样品流转时间线由 `sample_events` 专项视图呈现
- 不可修改：审计表只增不改不删
